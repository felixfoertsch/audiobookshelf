# Experimental inserted-audio candidates

## Fork container image

Fork development uses `main` at <https://git.felixfoertsch.de/felixfoertsch/audiobookshelf>. Every push to `main`, including documentation-only changes, runs `.gitea/workflows/fork-image.yml` on the `linux-builder` Gitea runner and publishes `git.felixfoertsch.de/felixfoertsch/audiobookshelf:main` for `linux/amd64`. Each build also publishes `:sha-<full-commit-SHA>` for commit-specific pulls. The workflow can also run manually on `main`; other branches cannot publish. Newer runs cancel older runs on the same branch.

```sh
docker pull git.felixfoertsch.de/felixfoertsch/audiobookshelf:main
```

For a new installation, use the repository's `docker-compose.yml` example and replace only its `image:` value with `git.felixfoertsch.de/felixfoertsch/audiobookshelf:main` (or a commit-specific tag). Keep its `13378:80` port mapping and persistent `/config`, `/metadata`, `/audiobooks`, and `/podcasts` mounts; adjust host paths for your installation. Back up existing config/metadata before choosing to run experimental builds against existing data.

Publication uses repository secret `REGISTRY_TOKEN`, sourced from the SOPS-managed Gitea container publisher credential; the built-in workflow token cannot authenticate to the registry. CI checks FFmpeg and full-duration Chromaprint in the built runtime before publication. This checks runtime compatibility, not inserted-audio detection accuracy. Image publication does not update or restart any deployed ABS service; pulling and deploying remain explicit operator actions.

## Optional analysis VPN proxy

Set server environment `AD_ANALYSIS_PROXY_URL=http://gluetun:8888` only on the new fork experiment. Leave existing stable production unchanged: exactly two ABS instances, stable plus one experiment, not a third instance. Use separate experiment config/metadata and media destinations; never share writable production state. Shared Gluetun infrastructure belongs to host provisioning, not this repository. Connect only Gluetun and the experiment to dedicated `vpn-egress` Docker bridge; do not publish proxy port or expose its control API. No keys or credentials belong in ABS configuration; host provisioning owns secret storage and runtime copies.

When unset, analysis retains direct SSRF-filtered transport. When set, all analysis catalog, RSS and comparison enclosure requests use HTTP CONNECT through this endpoint. Ordinary ABS downloads and playback remain direct. Only an HTTP proxy origin is accepted: no credentials, non-root path, query or fragment. Invalid configuration, refusal, timeout, TLS failure or tunnel loss fails analysis requests without direct fallback; catalog attempts record `invalid_analysis_proxy` or `proxy_failed_or_blocked` (timeouts use `request_timeout`). Evidence records `route: direct` or `route: vpn_proxy` without addresses or URLs. `vpn_proxy` means configured transport, not proof of VPN location or health. Identical fingerprints remain insufficient diversity.

The application resolves destination hostnames through the host's native trusted DNS resolver, rejects the entire answer set if any address is forbidden, and pins a validated literal IP in each CONNECT target. Proxy never resolves the original destination hostname. HTTPS still verifies the original hostname/certificate and sends its original SNI; HTTP Host stays original. Redirects repeat validation and consent checks under one absolute request deadline. DNS is local, not promised private or VPN-routed. This MVP deliberately does not implement VPN DNS or control Gluetun.

Gluetun's firewall setup precedes proxy startup, but the proxy can remain listening during VPN restarts; a listening proxy or cached healthy status does not prove tunnel security. ABS guarantees use of configured proxy with no direct transport fallback, not VPN firewall correctness. On 2026-10-19, deployment-specific acceptance on FFUNRAID verified the separate fork experiment managed by `felix ffunraid pv`, running amd64 ABS 2.37.1 from commit `d5eb501c`, with stable production unchanged and exactly two ABS instances. Its Gluetun Mullvad runtime uses IPv4 only. The deployed proxy reported a Mullvad exit; stopping the VPN loop produced three CONNECT denials while the proxy remained reachable, and restart recovery completed without any completed non-Mullvad HTTP request observed. These are host-specific acceptance results, not a universal firewall guarantee. Initial UI setup remains required; rollout created no accounts or libraries and did not enable podcast analysis.

## Analysis behavior

Disabled by default. Admins with library access/update permission can enable one podcast:

`POST /api/podcasts/:id/ad-analysis` with JSON `{ "enabled": true }`.

This authorizes public podcast title/author searches at Apple and gpodder.net, up to four public RSS fetches, and at most two extra audio requests per analysis. No accounts, private feed URL sharing, remote collectors, or playback-file changes. Existing classic player candidate skipping is described below. Optional server-side VPN proxy transport is described below. Disable with `{ "enabled": false }`. Existing episode reads never enqueue work.

Successful new downloads enqueue automatically. Retry an existing episode with `POST /api/podcasts/:id/episode/:episodeId/ad-analysis`, JSON `{}`. Response 202 means queued; 409 means disabled, duplicate, or queue full. Queue holds at most 32 jobs, concurrency one. Jobs are not durable; interrupted `running` results require explicit retry.

New durable attempts include ISO UTC `startedAt` and terminal `completedAt`; queued/running API overlays do not overwrite an older stored attempt. Failed results and catalog attempts include `diagnostic: { stage, reason }`: stages identify source/corpus/metadata/comparison, native version/decode/fingerprint, or catalog search/feed/audio; reasons use a fixed allowlist with `unexpected_error` fallback. Existing status/reason meanings and limits stay unchanged. Pre-save rejected jobs emit a sanitized lifecycle warning (item/episode IDs, `attempt` stage, `rejected` outcome, bounded reason); an invalidated initial load emits informational `not_started`, and cancellation is not logged as failure. Diagnostics retain no URLs, paths, public metadata, command arguments, native output, or arbitrary exception fields. Older results without timestamps remain readable; an overlay disappearing does not prove reexecution.

### Modern episode status

Modern podcast detail and Latest episodes show one analysis icon when the show opts in; disabled shows show none. Classic Vue episode rows remain unchanged. Labels/tooltips use localization-ready English fallbacks and accessible names. Candidate tooltip lists original-timeline break ranges; green never means verified ad-free.

| State | Public source | Modern label / action |
| --- | --- | --- |
| Not analysed | No result, downloaded audio | Not analysed; admin/root can queue |
| Queued / running | In-memory matching-source job | Analysis queued / Analysis running; spinning icon honors reduced motion |
| Candidates | `candidates` | Inserted audio found: N breaks, total seconds; tooltip lists ranges, not advertising proof |
| Compared, no difference | `no_difference`, reason `no_inserted_audio` | No inserted ads found; shared/baked-in ads may remain undetected |
| Inconclusive | `inconclusive` | Analysis inconclusive; admin/root can retry |
| Unsupported / unmatched | `unsupported`, no downloaded audio, `duration_limit`, or no matching catalog episode | Cannot analyse episode; grey link-off, explanatory tooltip |
| Failed | `failed` / `cancelled` | Analysis failed; admin/root can retry |
| Outdated | `stale` | Analysis outdated; admin/root can retry |

Legacy `inconclusive` results with an actual `samples[].status: no_inserted_audio` comparison normalize to `no_difference` on read, without changing stored evidence. Candidates, failures and stale results retain precedence. Identical fingerprints alone still do not prove absence of inserted ads. Recent episode JSON exposes `adAnalysisEnabled` from the parent show. Reads never enqueue.

`episode_ad_analysis` Socket.IO events carry `{ libraryItemId, episodeId, adAnalysis, adAnalysisEnabled }` on queue, start, completion and disable/cancellation, filtered through library-item access. Expanded podcast item responses expose public `adAnalysisEnabled` and project that owning boolean onto every nested episode, without exposing private `extraData` or requiring reverse associations. Modern detail rows use this explicit consent; missing consent stays off. Queued/running reads override prior stored results only for matching source signatures; completed reads still reject changed playback sources. Jobs remain in memory only, not durable across restart. Existing per-episode POST keeps server-enforced admin/root permission and show consent. Modern UI offers queue actions only for not analysed, inconclusive, failed and outdated states; queue failures remain visible and retryable.

Synthetic browser coverage verifies three candidate breaks, compared/no-difference caveat, queuing and live event updates. Historic Lateral 209 three-break and 210 no-difference results belong to older playback files; current source-bound evidence gives 209 two spans and 210 one, detailed below. Live UI acceptance still requires experiment deployment verification; local tests do not claim that acceptance.

### Retained comparison corpus

Completed comparisons persist under `global.MetadataPath/ad-analysis-corpus` (the configured experiment `METADATA_PATH`), separate from originals and ordinary item metadata. Each v2 version stores compact MPEG frame evidence (`frames.bin`), raw Chromaprint uint32 fingerprint JSON, SHA-256 digests for both, original downloaded-audio SHA-256/byte length as provenance, algorithm/version, provider, transport route, ISO collection timestamp and measured decoded duration. Downloaded catalog audio is transient, not retained in new versions. No URLs, credentials, addresses or original audio copies enter this corpus. Same URL can supply new versions on later explicit runs. Exact audio or fingerprint duplicates do not consume another slot.

Limits: five distinct comparison versions per episode, 10 GiB globally. Global accounting sums logical frame evidence, fingerprint JSON and manifest bytes across all episodes, plus legacy audio and recognized interrupted-migration files while present; filesystem blocks, directory overhead, temporary decode/staging and originals are excluded. Collection reserves headroom for 24 MiB frame evidence, 2 MiB fingerprint JSON and 4096 manifest bytes before catalog queries. Transient audio downloads remain bounded at 256 MiB. Thus collection can pause slightly below 10 GiB rather than download audio it cannot safely retain. Exact size is checked again before staging. Capacity never evicts or replaces evidence. No transient comparison bypass exists when collection is paused.

Each enabled run first validates and compares every retained fingerprint against the current hash-bound original, even at capacity, then collects within remaining capacity. Episode `adAnalysis.corpus` records inventory/count/global bytes and `collectionPaused`/`reason` (`episode_limit`, `corpus_limit`, or `corpus_unavailable`). Samples carry version ID, audio SHA-256, fingerprint SHA-256, comparison status and collection status. Full does not mean failed or ad-free. An independent read-only admin inventory survives restart, cancellation or stale results: `GET /api/podcasts/:id/episode/:episodeId/ad-analysis/corpus`. Library access remains required; GET never queues, downloads, or creates corpus files. Disabling denies explicit analysis, including offline comparison, but keeps evidence and permits admin inventory reads.

Private root (0700), files (0600), validated IDs/manifests, fixed filenames and symlink rejection protect stored paths. Single existing worker fsyncs the corpus root's metadata parent on each retain attempt (including retries after failed root creation sync), stages and fsyncs complete files and staging directory, rechecks consent/source/cancellation, atomically renames one new version directory, then fsyncs the corpus root. A failure after rename leaves published evidence in place and inventory counts it; an error response does not imply rollback. This follows the filesystem fsync protocol, not a universal power-loss guarantee. Failures clean that run's staging, not prior versions. Disk errors or corrupt/unexpected storage pause collection fail-closed; no automatic repair or pruning. Abrupt process/power loss can leave an unpublished `.stage-*` directory; it blocks collection until operator inspection rather than silently deleting possible evidence. This is single-process storage, not a multi-process coordinator. Inventory scans bounded manifests and file stats, not every audio byte; analysis verifies compact evidence/fingerprint hashes before reuse. Metadata backups must include this separate directory explicitly. No deployed/live podcast accuracy verification is claimed for this change.

#### Why retain compact evidence rather than markers only?

Markers alone suffice only while the exact local playback SHA-256 stays unchanged. They cannot recalculate boundaries after replacement, and deleting all comparison evidence would require another catalog download for every retry. MPEG alignment already operates on 48-bit frame hashes and Float64 frame times, not decoded speech: `MGF1` persists those exact values (14 bytes per frame plus 12-byte header). Comparing a changed original against this evidence reproduces the full-audio detector, including its existing hash-collision/format limitations. Chromaprint fallback needs only its retained uint32 fingerprint. Neither representation reconstructs playable catalog audio; raw audio would only be useful for a future detector/algorithm upgrade or listening audit, neither required by current code. New catalog versions still need a fetch to gain diversity. No detector thresholds change.

Migration is lazy, only during explicitly consented analysis (`load`), never GET inventory. Verify legacy audio/fingerprint hashes, derive and fsync `frames.bin`, fsync a replacement manifest, atomically publish v2 manifest, re-read/hash/decode compact evidence, recheck consent/source/cancellation, then unlink audio and fsync directory. Recognized interrupted states resume: legacy plus frames/temporary manifest, or v2 plus leftover audio. Unexpected files, corruption, symlinks or unsafe modes fail closed without deleting legacy audio. Back up corpus before rollout: old binaries cannot consume v2, so rollback requires restoring corpus backup or leaving analysis disabled. No migration writes to live corpus were performed during development.

Disposable-copy measurement of both live retained versions: 229303293 bytes before, 3566990 after (98.44% reduction). Episode 209: 110374608 → 1717160 bytes; 210: 118928685 → 1849830 bytes. Full-audio versus compact comparisons and migrated evidence produced identical markers for both current originals. Current 209 gives two candidate spans (0–29.100408 s, 2705.606531–2734.236735 s); current 210 gives one (0–30.119184 s). These are not the historic three/no-difference results: playback files changed, and this storage-equivalence check does not re-fetch catalog versions or certify advertising. Original SHA-bound stale rejection remains unchanged. Temporary corpus/DB/media copies were deleted after measurement.

Episode JSON includes `adAnalysis`: version, algorithm, status/reason, exact local playback `sourceSha256`, candidate segments in original seconds, catalog attempts and sample fingerprint evidence. URLs/paths are not evidence fields. Same fingerprint is insufficient diversity, never evidence of ad-free audio. Segments mark plausible insertion differences, NOT proof of advertising. Identical ads remain invisible. Classic client now marks candidate spans in its player track bar and `client/players/PlayerHandler.js` skips each candidate once while the same episode remains selected; seeking back into an already-skipped span plays it. The skipped-segment set resets when the episode ID changes, not on a same-episode reload. This existing behavior consumes `status: candidates` and segment times, not a fresh client-side file hash check. Modern playback intersects candidate spans with session duration, preserving raw server/corpus markers while clamping terminal ends to EOF. No cleaned export exists. Candidate status is not proof of advertising; clients adding new tag/skip behavior must bind results to the exact playback source. Changed filesystem identity/metadata or scanner audio metadata makes results stale; even harmless whole-file tagging invalidates results.

Docker installs Alpine community package `chromaprint`, which provides `/usr/bin/fpcalc` (verified Alpine v3.23 package contents). Outside Docker install native Chromaprint 1.5.x or 1.6.x and FFmpeg. Set `FPCALC_PATH` to executable absolute path, or put `fpcalc` on server PATH before startup; resolution is cached once. FFmpeg uses ABS `FFMPEG_PATH`. Missing/unknown fingerprint runtime returns `unsupported`, never blocks startup or playback. No automatic binary downloads added.

Decoder accepts only local-file protocol, normalizes to bounded mono 11025 Hz PCM in unique temporary directory outside library, and removes temporary files on completion/failure. Each decode/fingerprint has 180 s deadline; input max 256 MiB, duration 50 s–4 h. Catalog/feed responses max 2 MiB; redirects max four, every hop SSRF-validated. Ambient HTTP proxy settings never apply.

Each comparison first aligns MPEG Layer III frames byte for byte (`server/utils/mpegFrameAlignment.js`). DAI stitchers splice frames without re-encoding, so show content is byte-identical across copies; frames of the playback file outside the order-preserving shared runs (≥40 frames) are candidates, exact to one frame (≈26 ms), including prefix and tail inserts. Spans under 2 s are dropped, gaps under 3 s merged. Copies sharing under 65 % of frames, or non-MPEG audio, fall back to the Chromaprint path below; `samples[].method` records which ran. Probe across 37 shows on Megaphone, Acast, Art19, Simplecast, Omny/Triton, BBC, Podigee, Audioboom and WNYC found byte-identical show content on every host.

Timing uses Chromaprint TEST2 source constants from upstream tags v1.5.1/v1.6.2 `src/fingerprinter_configuration.{h,cpp}`: item period 1365/11025 seconds; window delay `(19*1365+2731)/11025`. Native fixture test exercises >120 s, two sample rates, equal/unequal-length creative replacements at non-frame-aligned middle/tail slots, silence controls, prefix rejection, and playback SHA preservation. Alignment runs in a bounded worker; multi-frame anchor index limits long-input candidate work. Boundaries move inward; prefix/tail differences remain untagged. With unanchored ends, internal spans additionally require local excess beyond splice uncertainty and no catalog gap beyond that uncertainty; anchored comparisons retain the existing replacement interpretation. Uncertainty combines hash-window width, two anchor strides, offset tolerance and Chromaprint delay. This is an empirical safety restriction, not proof of advertising or universal boundary correctness. Native safety coverage exercises 22 independently encoded cases at two rates, including long inputs reaching stride 5, plus the existing >120 s fingerprint fixture. The exact-SHA Gitea Linux native safety stage must pass before image publication; local macOS results do not establish that gate. This is not a speech accuracy guarantee: non-frame-aligned edits and recompression can remain inconclusive. The first fork workflow passed an amd64 container native fingerprint smoke and published amd64/arm64 images; ARM runtime behavior and real podcast accuracy remain unverified. Disabling cancels queued work and aborts active transport/native/worker processing; fresh consent, episode and file-identity checks precede every new external request, including redirects.
