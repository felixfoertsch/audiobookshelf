# Modern frontend action ledger

## Contract and evidence rule

Modern is only supported frontend. Classic remains reachable for legacy access but is not parity gate. This ledger maps Modern route surfaces and visible actions to owning source, permission condition, and test files. Paths are relative to `web/src` unless prefixed with `web/`. Working handlers and passing feature tests establish the supported state; they do not prove every conditional branch or production backend permission. Coverage limits stay explicit rather than being labeled unsupported. `Unsupported` requires visible explanation; absence of control is not automatically an unsupported explanation. Unmapped visible controls are audit findings, not support claims.

Safari/iOS and Cast hardware deferred to #8. Browser Cast code advertises direct-audio-only and hardware unverified (`web/src/features/player/CastControl.tsx:78`).

## Podcast counts and recency

Home and library grid both render `EntryCard`. Podcast cards use `PodcastEpisodeCount`; `PodcastEpisodeCount.test.tsx` tests `shows feed-wide unplayed total, not downloaded count` and `labels unavailable feed totals honestly`.

`GET /api/podcasts/:id/episode-summary` reuses server RSS parsing, cached for 30 minutes after successful resolution, with failed/null feeds cached for 60 seconds and at most 100 feed entries. Concurrent requests share in-flight work until resolution. Cards render downloaded counts immediately while summaries load. `PodcastEpisodeSummary.test.js` covers TTL boundaries, null/rejected failure caching, in-flight deduplication and oldest-entry eviction. `podcast-search-modal.spec.ts` holds summary responses pending to verify nonblocking cards, checks loaded visible latest covers (`naturalWidth > 0`) before captures, and rejects zero-duration shelf labels. Synthetic episodes without audio use zero duration; cards omit unknown/zero durations while retaining `audioFile.duration` fallback. Total counts downloadable entries currently present in RSS, not historical episodes removed by publisher. Unplayed means feed entries without a matched downloaded episode marked finished by current user (GUID, then enclosure URL). Missing/unavailable feed returns downloaded counts with explicit `downloaded · feed unavailable` label. Existing podcast model and serializers store downloaded episodes, not feed catalog totals. Browser never fetches RSS directly. Server evidence: `PodcastEpisodeSummary.test.js` — `counts feed episodes and uses matched downloaded user progress`, `falls back to downloaded episodes on feed failure`.

Classic recency remains unchanged: personalized Newest Episodes uses `publishedAt DESC` with a 60-day publication cutoff; legacy recent-episodes excludes finished downloads. Modern Latest and Newest Episodes opt into `GET /api/libraries/:id/recent-episodes?includeFeed=1&limit=50&page=0` (home uses limit 12). Opt-in merges all downloaded episodes, including finished downloads, with server-cached RSS entries, dedupes within each podcast by GUID then enclosure URL, sorts by numeric publication timestamp descending, then paginates. Default limit 50, maximum 200, zero-based nonnegative safe-integer page; invalid pagination returns 400. Authenticated library middleware plus explicit/tag filters and item access guard apply before reading feeds. At most 100 podcasts participate in deterministic ID order; feed requests run four at once through `getCachedPodcastFeed`, never direct browser RSS. Existing 30-minute success/60-second failure cache and in-flight dedupe remain shared. Response adds `downloaded` per row and top-level `feedUnavailable`/`feedTruncated`; missing feeds retain downloaded rows and Latest explains fallback. Feed rows carry stable nonplayable IDs, podcast/library item IDs, full enclosure, GUID, title, publication timestamp and duration seconds. No per-podcast episode cap: 262-entry feeds remain pageable.

Feed-only rows show disabled Play with “Not downloaded”, disabled player-queue/listening-status actions, and labeled/tooltip download icon for root/admin users whose update/download permissions are not explicitly denied. Native `POST /api/podcasts/:id/download-episodes` receives an episode array including enclosure and GUID; server's existing admin/update authorization stays authoritative. Download queue API and existing `episode_download_*` socket events expose Queued/Downloading/failure and refresh data on completion; row becomes playable without page reload. Feed-only rows never render ad analysis. Original audio and detector remain untouched.

Evidence: `LibraryRecentEpisodes.test.js` covers merge/GUID and enclosure dedupe, ordering/pagination, real library/explicit/tag denial, query/serializer contract, legacy compatibility, invalid pagination, four-request concurrency, 100-podcast truncation, flagged unavailable-feed fallback and complete 262-entry pagination. `feed-episodes.test.tsx` covers permission gates, native POST payload, queued/started/finished socket lifecycle and listener state. `feed-episodes.spec.ts` covers mixed rows, download-to-playable transition and screenshots at root and `/abs`, 1280/390, light/dark; also home data/link/action and listener denial. Live read-only check confirmed Dick & Doof: 262 feed entries, 8 downloaded; RSS duration is a string plus numeric `durationSeconds`, full enclosure has `url`, `type`, `length`. No live downloads triggered.
