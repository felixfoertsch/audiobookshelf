# Full Classic → modern frontend parity audit

## Contract and evidence boundary

Full parity is completion criterion, not a thin podcast slice. Every existing piece of information, actionable control, permission boundary, state and reachable workflow needs a working modern home. Preserve existing information architecture and canonical route paths; modern preview adds reversible `/new` prefix only. Backend APIs, authentication, database, filesystem/media ownership and deployment structure stay unchanged. Exactly two deployed instances remain: stable production and existing fork experiment. This document authorizes no deployment, root switch, data mutation or new instance.

Classic remains default unless `MODERN_WEB_DEFAULT=true` explicitly enables alpha landing. Operator separately approved incomplete-parity first alpha as default only on existing experimental `podcast.felixfoertsch.de`; stable/full-parity cutover remains unapproved. See `frontend-migration.md` for selection and rollback. Classic links remain useful escape hatches during implementation, but **never count as ported behavior**. Decorative, disabled-without-reason or dead buttons do not count. Modern layout may change visually; functionality and discoverability may not disappear.

Audit basis: Classic `client/pages` (42 Vue files), `client/nuxt.config.js`, default/blank/error layouts, page-linked components, player/readers, store actions, middleware, API mounts and `server/Server.js` dynamic route list. Current React route/loader/player source inspected under `web/src`. This is a source-backed requirement inventory, **not runtime certification or exhaustive branch/button test coverage**. Component source pointers below are implementation checklists; owners must walk each conditional tab, menu, table row and dialog against Classic before signing off. No workflow is marked verified here.

### Route derivation, including non-file routes

- Real generated artifact now inspected: `client/node_modules/.cache/nuxt/router.js`, with router base `/classic/`. Node assertion extracted actual route records, flattened parent/child paths and compared sorted leaf paths against all 41 ledger rows: exact equality, no missing or extra paths. This verifies route inventory, not runtime behavior; all rows remain U. `client/nuxt.config.js` sets router base; no custom route extension found.
- Initial source reproduction used `createRoutes`, `sortRoutes`, `cleanChildrenRoutes` and `getRoutePathExtension` from locked `@nuxt/utils@2.18.1` (<https://unpkg.com/@nuxt/utils@2.18.1/dist/utils.js>; version from `client/package-lock.json`). Real generated artifact comparison above now supersedes reproduction-only evidence.
- Result: **42 component records, 41 leaf route records, 41 distinct leaf paths**. `config.vue` is parent shell, not extra screen beyond `/config` rendered by `config/index.vue`. Nuxt's optional parameters are shown exactly, including surprising `:library?` on sibling routes. Valid links still supply library/item IDs; missing-ID paths need old redirect/error behavior, not invented screens.
- Express explicitly mounts **21 dynamic patterns**, not 21 extra screens. `/library/:library/authors` has no matching page file; current navigation uses `/library/:library/bookshelf/authors`. `/library/:library/series` and `/config/item-metadata-utils/:id` likewise accept server deep links without proving useful missing/unknown-ID client screens. Preserve transport reachability and audit resulting client state, not silently advertise fabricated pages.
- API/auth/media/feed/socket routes are contracts, not frontend screen count. `GET /login` is screen; `POST /login` is auth endpoint. Never prefix backend contracts with `/new`.

Paths below are relative to actual external `RouterBasePath`. Every leaf has exact modern partner `/new` + old path (`/` becomes `/new/`), with search/hash preserved. No pluralization redesign. Existing preview `/new/libraries/:libraryId` and `/new/items/:itemId` are temporary noncanonical paths; later implementation must move internal links/loaders to `/new/library/:library` and `/new/item/:id`, retaining plural paths only as explicit compatibility redirects. This audit changes no routes.

## Integrated surface updates

- Podcast detail and latest-episode rows expose source-bound ad-analysis status, live authorized queue updates and admin/root-only retry. A no-difference result does not rule out shared or baked-in ads. Reading status never queues analysis.
